# Abendstudium — 教授の書斎

銀髪のアドラー教授と、毎日少しずつドイツ語を学ぶ静的Webアプリです。HTML / CSS / JavaScriptのみで動作し、ビルドは不要です。既存の家事管理・プロジェクト管理アプリとは独立しています。

## 小説で学ぶドイツ語（Literaturstudium）

『中身で選んだ夫が、顔まで理想だった件』全5章・330件の対訳教材を追加しました。章／教材種類の選択、一文ごとの音読・単語比較、端末標準の読み上げ、学習済み登録と続きからの再開に対応します。

件数、抽出方針、変更ファイル、iPhoneの確認手順、公開方法は [LITERATURSTUDIUM.md](LITERATURSTUDIUM.md) をご覧ください。教材CSVは [data/mythos_novel_b1.csv](data/mythos_novel_b1.csv) です。小説モードへは組み込み済みなので手動インポート不要です。

## 教授の朗読音声

全5章の教材330件に教授の音声を収録しています。「お手本を聴く」で再生し、音声ファイルを取得できない場合は端末のドイツ語読み上げを使います。新規の再生速度は0.9倍です。「読み上げ速度」から変更でき、以前に保存した速度も引き継ぎます。音声ファイルは元の速さで保存し、再生時にピッチを保って速度を調整します。

褒め言葉8本、励まし5本、学習終了4本を収録しています。ブラウザが自動再生を許可しない場合は「教授の声を聴く」ボタンで再生できます。

## 最初に知っておくこと

- Supabase未設定でもローカル体験モードで使えます。データはこのブラウザのlocalStorageに保存されます。ブラウザデータを消すと失われるため、JSONバックアップを取ってください。
- Supabaseを設定してログインすると、本人の学習データをクラウドに保存します。MacとiPhoneで同じアカウントを使えます。別端末の変更はページ再読み込みで取り込みます。
- ご提供の教授イラスト4枚（通常・読書・笑顔・紅茶）とB1/B2の例文12件を同梱。音声ファイルはまだ同梱していません。未登録の音声は「準備中」と表示されます。
- 有料AI APIは使用しません。通常レッスンのお手本・称賛は事前録音ファイルの再生です。小説モードでは無料の端末標準読み上げを利用し、将来の録音差し替えにも対応します。
- リポジトリ作成、GitHub Pages公開、Supabaseプロジェクト作成・SQL適用はまだ実施していません。

## 1. 手元で開く

このフォルダーでターミナルを開き、Python 3がある場合は次を実行します。

```sh
python3 -m http.server 4173
```

ブラウザで http://localhost:4173 を開きます。終了はターミナルでControl+C。
HTMLファイルのダブルクリック（file://）ではJavaScriptモジュールとPWAが正しく動作しません。Pythonがない場合は、先に次のGitHub Pages公開を行ってください。

## 2. GitHub Pagesに公開する

1. GitHubで、このアプリ専用の新しいリポジトリを作成します。既存アプリのリポジトリは使いません。
2. このフォルダーの**中身**をリポジトリ直下にアップロードします。index.html、assetsフォルダー、各JS/CSS、manifest.webmanifest、sw.js、config.jsが必要です。`abendstudium`フォルダーごと入れて階層を1段増やさないようにします。
3. リポジトリの Settings → Pages → Build and deployment で「Deploy from a branch」を選び、main / root を指定して保存します。
4. デプロイ完了後、Pages画面に表示されたHTTPS URLを開きます。通常は `https://ユーザー名.github.io/リポジトリ名/` です。
5. すべて相対パスなので、リポジトリ名の下でも動作します。

公開リポジトリ・静的サイトのファイルは誰でも読めます。学習データのJSONバックアップ、録音した個人情報、.env、秘密キーはアップロードしないでください。バックアップを保存するならGit管理外の場所を使ってください。

## 3. Supabaseを設定する

1. [Supabase](https://supabase.com/)でアカウントを作り、このアプリ用の無料プロジェクトを作成します。無料枠の上限や休止条件は管理画面で確認してください。
2. SQL Editorで `supabase.sql` の全文を貼り付けて実行します。専用の `study_states` テーブルと保存関数を作ります。他アプリのテーブルは変更しません。
3. プロジェクトの接続設定から **Project URL** と **publishable key**（`sb_publishable_...`）を確認します。旧形式の `anon` keyも使えます。
4. `config.js` を編集します。

```js
export const config = {
  supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
  supabaseKey: 'sb_publishable_YOUR_PUBLIC_KEY'
};
```

5. **secret key（sb_secret_...）、service_role key、DBパスワードは絶対に記入しないでください。** 公開キーでもRLSが必須です。
6. Supabase Authentication → ProvidersでEmailを有効にします。メール確認を有効にすることを推奨します。
7. Authentication → URL ConfigurationのSite URLにPagesの完全なURL（リポジトリ名・末尾 `/` を含む）を設定し、Redirect URLsにも同じURLを登録します。ローカル開発時は `http://localhost:4173/` も登録します。
8. 更新したconfig.jsをGitHubへアップロードし、公開ページを再読み込みします。「ログイン / アカウント」から新規登録し、確認メールのリンクを開いてログインします。メールの受信・送信制限はSupabaseの設定に依存します。
9. 1件学習して、Supabase Table Editorのstudy_statesに自分の行が保存されたことを確認します。初期例文は初回保存時に登録されます。

設定済みのSupabase接続情報は維持しています。小説機能追加によるSQLの再実行は不要です。

認証SDKは `https://esm.sh/@supabase/supabase-js@2.49.1` から固定バージョンを読み込みます。設定前の体験モードでは外部SDKに依存しません。ログイン後の起動・保存には通信が必要です。クラウドの読込・保存に失敗した場合はローカルに自動退避せず、未保存のメッセージを出します。

ローカルの体験データとアカウントのデータは分離されています。移行する場合は、体験モードでJSONを書き出し、ログイン後にそのJSONを読み込んでください。ログアウトすると体験モードに戻ります。

## 4. 学習方法

- 「今日のレッスン」は現在時刻までに復習期限が来た例文を古い順に抽出します。
- 訳はボタンで表示・非表示。文法・語彙は折りたたみノートにあります。
- 忘れた：10分後。少し迷った：前回間隔×1.2（最低1日）。覚えていた：最初は1日、その後×2.5（最大365日）。簡易的な間隔反復方式で、FSRS/SM-2の実装ではありません。
- 1日の上限は端末の現地日付で数える異なる例文数です。「忘れた」の再復習は同日の上限到達後も出題されます。日付は端末のタイムゾーンに従います。
- 「例文の本棚」で登録・編集・カテゴリー検索ができます。編集しても復習間隔と履歴は保持します。
- 「学習の記録」は直近7日間の復習回数、総数、最近50件の学習・発音結果を表示します。JSONには全履歴が含まれます。
- 複数端末で同時に保存するとrevisionの競合を検知して上書きを止めます。メッセージが出たら再読み込みし、必要な操作をやり直してください。リアルタイム同期・オフラインのクラウド保存キューはありません。

## 5. 発音練習とiPhone

1. 音声を登録済みなら「お手本を聴く」を押します。
2. de-AT（オーストリア）を初期値とし、de-DE（ドイツ）にも変更できます。言語選択は認識サービスへの指定であり、その地域モデルの提供を保証するものではありません。
3. 「マイクで練習」を押すと、再生中の音声を止めてから音声認識を開始します。自動でマイクを開始することはありません。
4. 認識結果は自動比較されます。手入力やキーボード音声入力の場合は「文章を比較する」を押します。
5. 大文字小文字と句読点を除外して、単語単位の編集距離で比較します。ウムラウト、ß、語順の違いは保持します。欠落・余分・置換の単語を色と文字で示します。
6. 一致度は `100 × (1 − 単語編集距離 / 両文の長い方の単語数)`（最低0%）。**発音品質の採点ではありません。** 数字表記や略語の違いでも一致しない場合があります。
7. 完全一致時は教授が笑顔になり、称賛音声が設定済みなら再生を試みます。ブラウザが自動再生をブロックするとメッセージが出ます。不一致時は再挑戦の台詞を表示します。
8. 結果の文章・一致度・日時・言語・入力方式を保存します。マイクの生音声をアプリやSupabaseに保存しません。ブラウザ側の認識サービスへ音声が送信される場合があります。

Safariでは `SpeechRecognition` / `webkitSpeechRecognition` を機能検出します。HTTPS、マイク許可、端末の音声認識設定や通信状態が必要です。Safari・iOS・PWAの組み合わせによっては利用できないため、標準音声入力の入力欄を常に利用可能にしています。必要ならSafariの通常タブでもお試しください。

認識が非対応／拒否された場合は、入力欄を選び、iPhoneのドイツ語キーボードの音声入力を使います。設定 → 一般 → キーボードでドイツ語キーボード・音声入力を有効にしてください。利用可否は端末設定によります。

## 6. 教授・音声を差し替える

`character.js` がキャラクター設定です。

- images.neutral：通常画像
- images.smile：発音練習の文章が完全一致したときの笑顔画像
- images.book：文法と語彙のノートを開いたときの読書画像
- images.tea：現在出題できる例文がなくなったときの休憩画像（次の復習待ち・日次目標到達）
- alt：各画像の読み上げ用説明
- lines.welcome / praise / retry：台詞
- audio.praise / retry：事前録音のMP3等のパス

例：`audio: { praise: 'assets/audio/praise.mp3', retry: 'assets/audio/retry.mp3' }`

例文音声は `assets/audio/` に録音済みファイルを入れ、「例文の本棚」→ 編集 → 音声パスに `assets/audio/lesson-01.mp3` と指定します。HTTPSの外部URLも使えますが、閲覧可能な配信元が必要です。iPhoneではMP3/AACなど対応形式を使用してください。

初期例文はseeds.jsで編集できます。既に作成された学習データには自動反映されないため、本棚の編集またはインポートを使ってください。画像の縦横比が違う場合はstyle.cssのportraitを調整します。ご提供のPNGをそのまま使用し、縦長の全体が収まる表示にしています。画像はPWAのオフラインキャッシュにも含みます。

## 7. CSV / JSON

CSVの列名は次のとおりです（germanは必須）。UTF-8、カンマ区切り、引用符・改行入りフィールドに対応します。

```csv
german,japanese,grammar,vocabulary,category,level,audio
"Ich freue mich auf morgen.","明日が楽しみです。","auf + 対格","sich freuen：楽しみにする","日常","B1",""
```

CSV・例文配列JSONは新しい例文として追加します（重複も追加されます）。アプリのバックアップJSONは確認ダイアログ後に例文・履歴・設定を置き換えます。全体を検証してから保存するので、不正な入力を部分的に取り込みません。最大2000例文・読み込み5MBです。履歴が大きくなった場合はバックアップしてデータ整理してください。Supabase保存も5MB以内です。

CSVを表計算ソフトで開く場合、取り込んだ文章が数式として解釈されないよう、列の形式をテキストとしてインポートしてください。

## 8. PWA / オフライン

iPhoneはSafariの共有メニュー → ホーム画面に追加。Macは対応ブラウザのインストール機能を使用します。manifest・192/512pxアイコン・Apple touch icon・Service Workerを同梱しています。
初回オンライン読み込み後、アプリの画面とローカル体験データはオフラインで使用できます。認識サービス、Supabase、外部音声はオンラインが必要です。音声ファイルは自動キャッシュしません。サービスワーカーは自サイトの指定した画面ファイルのみをキャッシュし、認証情報・DBレスポンスは保存しません。
更新時はsw.jsのCACHE末尾（現在v5）をv6等に変更します。旧タブをすべて閉じて再度開くと、新バージョンへ切り替わります。Safariが保存容量を回収する場合もあるため、オフライン保存をバックアップ代わりにしないでください。

## 9. セキュリティと検証

- study_statesのuser_idはauth.usersに紐づき、RLSのUSING/WITH CHECK両方でauth.uid()との一致を要求します。
- 保存RPCはSECURITY INVOKER。認証が必要で、RLSを迂回しません。anonにはテーブル・RPC権限を付与していません。
- 学習内容はinnerHTMLで挿入せずtextContentを使い、音声URLはHTTPSか相対パスに制限します。
- 学習データは利用者ごとにJSONBの1行で保存します。例文・履歴・練習結果・設定をまとめて更新し、復習だけ保存されて履歴が欠ける問題を避けます。大規模運用に向けた正規化は未実施です。
- Supabase標準のブラウザセッション保存を使用します。共有端末ではログアウトしてください。外部SDKを含む依存関係は定期的に点検してください。

自動テスト（Node.js 20以降）：

```sh
npm test
```

比較、単語の差分、3評価の復習間隔、日次上限、CSV往復、入力検証、小説教材・進捗・操作連携、音声ライフサイクルの18テストを実行します。追加インストールは不要です。

### 公開前の実機チェック

- Supabaseにテスト用A・Bの2アカウントを作り、AのデータがBから読めず、Aのuser_idでBが書き込みできないことを確認します。SQL Editorの管理者接続はRLSを迂回するので、この検証はブラウザの認証済みクライアントで行います。
- ログアウト状態ではデータAPIへのアクセスが拒否されることを確認します。
- 2つのタブで同じrevisionを読み、片方を保存した後にもう片方を保存すると競合が表示されることを確認します。
- iPhone Safariでマイク許可・拒否、de-AT/de-DE、認識結果比較、標準音声入力、音声停止を確認します。
- MP3追加後、お手本・称賛音声を確認します。ホーム画面追加後も動作確認します。
- JSONバックアップの往復、CSVの追加、別ユーザーのログアウト／ログインを確認します。

作成環境では自動テスト18件とJS構文・HTML参照検査を実施済みです。ローカルHTTPサーバーの起動は実行環境の権限制限でできなかったため、ブラウザ表示・実機マイク・Supabase実接続・RLSの2ユーザー実行テストは未実施です。
